# NixOS Dotfiles

"I use Nix btw"

![System Showcase](pics/demo.png)

One desktop on both machines: **X11 + dwm**. There used to be a Wayland session
(dwl) as well; carrying two of every module, one per session, cost more than the
second WM was worth. It is in the git history if it ever comes back.

## Layout

```
flake.nix                 the host table and the nixosSystem factory; no config here
hosts/
  common.nix              what every host shares: the fork overlay, boot, nix,
                          users, locale, sound, X + dwm, docker, tailscale
  home.nix                the user profile: apps, shell, what the session starts
  <host>/configuration.nix        host deltas: keymap, NVIDIA + PRIME, (nixbox1) VMs
  <host>/home.nix                 host facts: wallpaper, xrandr line
  <host>/hardware-configuration.nix  generated by nixos-generate-config
src/                      vendored C sources (dwm, st, slock, slstatus)
patches/                  where each local C change came from (see patches/README.md)
pics/                     wallpapers
```

Nine `.nix` files, two of them generated. The flake exports
`nixosConfigurations` and nothing else.

## The two rules this repo runs on

**1. Layers never reach across each other.**

| layer                                          | knows about              | never mentions          |
| ---------------------------------------------- | ------------------------ | ----------------------- |
| `hosts/<name>/`                                | this machine             | the WM, other hosts, usernames |
| `hosts/home.nix`                               | one user profile, every machine | connector names, hostnames, GPUs |
| `hosts/common.nix`                             | everything shared        | specific hosts          |

**2. Host facts flow through options, not hardcoding.** `hosts/home.nix`
declares a `vars` namespace; the host fills it in and the same module turns it
into what the session runs:

```nix
# hosts/nixbox1/home.nix
vars.wallpaper = ../../pics/2077.png;
vars.xrandrArgs =
  "--output eDP-1 --auto --primary "
  + "--output HDMI-1-0 --mode 2560x1440 --rate 144 --right-of eDP-1";
```

Connector names are whatever `xrandr -q` prints on that machine, listed in the
order xrandr must apply them, because it resolves `--right-of` only against an
output it has already seen. No `xrandr` line (nixbox2, built-in panel only) means
X keeps the panel's preferred mode. The wallpaper ends up linked at
`~/.config/wallpapers/bg.png`; neither fact is spelled out inside a session.

Usernames work the same way: the host table in `flake.nix` is the only place
`anon` appears. `hosts/common.nix` creates the accounts with the groups the
always-on features need, and a host adds its own when it enables something that
needs one (`libvirtd` on nixbox1).

The GPU is the one host fact that needs no `vars` namespace: a host simply sets
nixpkgs' own `hardware.nvidia` options, so its whole PRIME setup sits in
`hosts/<name>/configuration.nix` next to the rest of its hardware. The two
blocks look alike and differ in exactly one thing, the driver generation
(`open = true` on nixbox1, `legacy_580` on nixbox2) -- and that duplication is
the point: a GPU is a machine fact, so it belongs to the machine.

## Hosts

| host    | notes                               |
| ------- | ----------------------------------- |
| nixbox1 | nvidia (open), JP, panel + HDMI, VMs |
| nixbox2 | nvidia (legacy 580), US, panel only  |

Both are in the host table at the top of `flake.nix`, which is the only place the
flake looks: a missing host file or a missing `system`/`users` key fails
evaluation instead of silently importing nothing.

**Adding a host**

1. `hosts/<name>/hardware-configuration.nix` — from `nixos-generate-config` on the box.
2. `hosts/<name>/configuration.nix` — import it, set the keymap, set `hardware.nvidia` with this machine's bus ids, add anything only this machine runs.
3. `hosts/<name>/home.nix` — `vars.wallpaper` and `vars.xrandrArgs`.
4. Add the entry to the host table in `flake.nix`.

## Vendored forks

`src/` holds hand-patched copies of dwm, st, slock and slstatus. They are defined
**once**, by an overlay in `hosts/common.nix` -- the one module both halves see,
since the forks are used from the system (dwm, slock) and the home (st,
slstatus) side alike:

* `patches = [ ]` — upstream's patch list is dropped on purpose; the local
  changes are carried in the source (provenance: `patches/README.md`).
* `version = "<upstream>-local"` — so a fork rebuild is visible in
  `nixos-rebuild` output (`dwm-6.6-local`, `st-0.9.2-local`, ...) instead of
  being name-identical to upstream.
* `src = lib.cleanSource ...` — editing docs or patch notes next to the source
  cannot invalidate the derivation.

Rebasing a fork onto a new upstream release: copy the new release over
`src/<pkg>`, re-apply the entries in `patches/<pkg>/`, keep the local
`config.def.h`.

## Commands

Run from this repo; swap `nixbox1` for `nixbox2`.

```sh
nixos-rebuild switch --flake .#nixbox1       # build + activate
nixos-rebuild build  --flake .#nixbox1       # build only, change nothing
nixos-rebuild switch --flake .#nixbox1 next  # + set as default boot entry
nixos-rebuild reboot --flake .#nixbox1 next  # switch + reboot
nixos-rebuild dry-activate --flake .#nixbox1 # preview changes, touch nothing
```

- Build fails → add `--show-trace`.
- Bad switch → `sudo nixos-rebuild --rollback` (or pick the previous
  systemd-boot entry at the bootloader).
- Checking the host you are *not* sitting on, without building anything:

  ```sh
  nix eval ".#nixosConfigurations.nixbox2.config.system.build.toplevel.drvPath"
  ```

## Garbage collection

Automatic: `nix.gc` in `hosts/common.nix` runs weekly with 14 day retention. By
hand:

```sh
sudo nix-collect-garbage -d
```

No CI, no linters, no `devShell`, no formatter output — this repo is only what
the two machines need. If you ever want a pre-commit or eval-on-push gate, the
hooks live cleanly in `flake.nix` (`checks`) or `.github/workflows/`.
